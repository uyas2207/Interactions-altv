## Сервер

При входе игрока проверяется записаны ли в map playerInteractions у игрока с таким id выполненные или активные интеракции, если их нет создаются все, если есть то создаются только те которые считаются активными.
Те интеракции которые считаются активными в map playerInteractions создаются на клиенте (колшейпы и маркеры под соответствующие интеракции) через `alt.emitClient(player, 'client:sceneDemo', activeInteractions);`

При выполнении интеракции на сервер приходит информация с типом выполненной интеракции и вызывается метод `completeInteraction`, который меняет данные об активных и выполненных интеракциях у игрока с таким id в map playerInteractions и отправляет игроку запрос удалить визуальные части (маркер и колшейп) для соответствующей интеракции.

Еще на сервере есть команда для пересоздания конкретной точки интеракции по команде `/create 1,2,3` с проверкой от повторного создания уже существующей на клиенте точки.

## Клиент

### Основной класс Interaction

При запросе от сервера создает визуально маркер и колшейп для точки интеракции через класс `PointVisuals`. (информация о координатах и характеристиках колшейпов и маркеров берется из `config/InteractionConfig.js`)

При запросе с сервера удаляет визуально маркер и колшейп для точки интеракции через класс `PointVisuals`.
  
При входе игрока в колшейп проверяет дистанцию игрока относительно колшейпа (проверка от читеров) после этого создает активную интеракцию в соответствии с `InteractionType` колшейпа (ее визуальную составляющую Webview + класс с ее логикой).
При выходе из колшейпа удаляет активную интеракцию.    

### Классы для Webview

- **NotificationBase** - базовый класс шаблон для наследования в классах `TapCounter`, `ProgressBar`, `PersistentNotification`
    
    - стандартные методы `show`, `update` (меняет текст в текущем Webview), `hide`
        
- **NotificationManager** - основной singletone класс для управления Webview (работает так же как NotificationManager в прошлом задании на систему доставки)
    
    - Инициализирует Webview при запросе класса Interaction
        
    - Создает Webview ProgressBar при запросе класса Interaction
        
    - Создает Webview TapCounter при запросе класса Interaction
        
- **TapCounter** - наследует методы `NotificationBase` и адаптирует под TapCounter + хранит и изменяет информацию о текущих данных: `title`, `currentTaps`, `requiredTaps`, `text`
    
- **ProgressBar** - наследует методы `NotificationBase` и адаптирует под ProgressBar + хранит и изменяет информацию о текущих данных: `title`, `progress`, `text`
    
- **PersistentNotification** - наследует методы `NotificationBase` и адаптирует под PersistentNotification + хранит и изменяет информацию о текущих данных: `title`, `text`
### Классы для логики интеракций

- **InteractionBase** - шаблон для классов наследников
    
    - есть общий метод для дебаунса от спама кнопки
        
- **HoldInteraction** - вызывается при входе игрока в соответствующий тип колшейпа
    
    - создает webview для ProgressBar
        
    - при нажатии на E проверяет есть ли активный процесс, если нет вызывает метод для прогресса (`runProgress`) через `currentProgressPromise`
        
    - `runProgress` выполняет 10 циклов, каждый цикл меняет отображение значений в webview и запускает 1 промис с resolve и reject. resolve выполнится через секунду ожидания, reject (интервал с проверкой `this.progressShouldStop` раз в 200 миллисекунд) произойдет в случае если игрок отпустил E или вышел из колшейпа (при выходе из колшейпа и отпускании кнопки ставится `this.progressShouldStop = true`)
        
    - в случае успешного выполнения отменяет анимацию и передает на сервер информацию об успешном завершении интеракции
        
    - в случае прерывания прогресса отменяет анимацию и ставит webview в начальное значение
        
    - в случае успешного или неуспешного завершения обнуляет `currentProgressPromise`
        
    - скрывает webview, обнуляет прогресс `currentProgressPromise` (если он есть), очищает обработчик нажатия и обработчик отпускания клавиши при удалении колшейпа или выходе из колшейпа
        
- **MultiTapInteraction** - вызывается при входе игрока в соответствующий тип колшейпа
    
    - создает Webview для TapCounter
        
    - при нажатии на E запускает анимацию и меняет webview для отображения оставшегося количества нажатий и так пока не будет выполнено 10 нажатий
        
    - скрывает webview и очищает обработчик нажатия на клавишу при удалении колшейпа или выходе из колшейпа
        
- **SingleTapInteraction** - вызывается при входе игрока в соответствующий тип колшейпа
    
    - создает Webview для PersistentNotification
        
    - при нажатии на E запускает анимации и спавн пропа, пишет об успешном завершении и передает серверу информации о завершении конкретного типа интеракции
        
    - скрывает webview и очищает обработчик нажатия на клавишу при удалении колшейпа или выходе из колшейпа
        

### Класс для анимаций AnimationManager
(пока что в нем логика только для анимации в интеракции VENDING)

Перезагружает анимации при входе клиента на сервер, если еще не загружены

Ставит игрока на конкретную точку, создает проп банки с колой, приклеивает проп к руке и запускает анимации (информация о пропе, координатах и т.д. берется из `config/InteractionConfig.js`)
